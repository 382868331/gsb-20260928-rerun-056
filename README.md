# 资金流动推演系统（第二轮：调拨延误后的剩余计划重规划）

根据虚构账户、已知收支和账户间调拨限制，按日推演未来各时段的资金缺口，
产出可按时间重放的调拨计划；场景、计划、实际执行记录分别持久化。
第二轮支持在某个「重开日（截断日）」早晨，基于已发生的实际事实重新规划
剩余可执行计划：已发出资金保持在途、不重复占用，到账时间/到账金额/手续费
变化后重新评估每笔支付的期限与费用，可推迟可选支付或选用更贵但及时的路径，
并把选择理由与未满足部分写清；修订计划与实际执行记录分开保存，重开后可全程对账。

## 核心约束

- **到账时间参与计算**：调拨有 `lag_days`，发起日付款方立即扣本金+手续费，
  到账日收款方才可用；在途资金任何一方都不能使用。
- **手续费参与计算**：按比例+固定额，发起日实时占用资金；余额不足以覆盖
  “本金+手续费”时调拨不允许发起。
- **不能用没到账的钱支付**：每日过账顺序固定为
  收入到账 → 调拨发起 → 调拨到账 → 支出支付；当日到账资金不能当日再发起
  下一跳（同日多跳链被拒绝）。
- **同一笔钱不安排两次**：过账时账户余额严禁为负，不足即报错；单号唯一。
- **目标排序**：先把 P1→P2→P3 支出缺口降到最小，再最小化总调拨手续费
  （目标元组 `(P1缺口, P2缺口, P3缺口, 总费用)` 字典序）。

## 第二轮：中断重规划语义

- **截断日（cutoff）早晨重开**：先把 `[start, cutoff-1]` 的实际执行（实际发起/
  到账、实际收入到账）重放一遍，得到各账户真实现金与仍在途的调拨。
- **已发出资金不重复占用**：截断前发起的调拨记入 `committed_orders`；其中
  截断日早晨仍在途的笔作为「在途预载」，只等到账，重规划绝不再从原账户动用
  其本金。守恒式加入「期初在途本金」：
  期末余额 + 在途 + 手续费 = 期初余额 + 期初在途 + 收入 − 已付支出。
- **到账变化后重估期限与费用**：`ActualInflow` 支持收入延迟/部分到账；
  `RuleChange` 记录某日生效的费率/到账天数调整，仅影响生效日后新发起的调拨，
  在途调拨沿用发起时条件。
- **两类取舍并写明理由**：允许把可选 P3 支付推迟到资金更宽松的日期
  （枚举推迟组合，仅当确实减少缺口金额才采纳），或选用费率更高但能按时到账
  的加急路径；每条新增调拨在 `choices` 中给出理由，仍无法满足的进入
  `remaining_gaps`，推迟进入 `deferrals`。
- **三类数据分开持久化**：`data/scenarios|plans|executions|revisions/`，
  修订计划保存为 `revisions/<scenario>__rev<n>__<time>.json`，可反复重开、
  多版本并存；`replay_full` 用「实际前缀 + 修订后缀」全程重放对清资金去向。

## 目录

- `cashflow/models.py`：账户、收支（含优先级）、调拨规则（到账天数/手续费/限额）
- `cashflow/scenario.py`：场景，校验并独立存取 JSON
- `cashflow/ledger.py`：时序账簿与资金守恒核对（重放内核）
- `cashflow/engine.py`：基线推演、按订单重放、贪心求解器（反向 DFS 选最便宜调拨链）
- `cashflow/solver_brute.py`：小规模残差 DFS 枚举求解器，用于小例子对拍
- `cashflow/plan.py`：计划 `Plan` 与实际执行 `Execution`，分文件保存
- `cashflow/replan.py`：截断重放、剩余场景构造、P3 推迟枚举、`RevisedPlan`
- `examples/run_delay_demo.py`：两跳中途延误 + 部分收入 + 费率提高全过程
- `cashflow/repo.py`：`data/scenarios|plans|executions/` 三类数据分目录
- `cashflow/report.py`：事件清单、每日各账户资金账、缺口位置、对账报表
- `examples/run_demo.py`：三账户小例子，枚举与贪心对拍
- `tests/`：11 个单元测试

## 运行

```bash
.venv/bin/python -m examples.run_demo          # 小例子全流程演示
.venv/bin/python -m unittest discover -s tests # 测试
.venv/bin/python -m cashflow baseline data/scenarios/demo01.json
.venv/bin/python -m cashflow solve data/scenarios/demo01.json --brute
.venv/bin/python -m cashflow replay data/scenarios/demo01.json <plan.json>
.venv/bin/python -m examples.run_delay_demo       # 第二轮延误重规划演示
.venv/bin/python -m cashflow revise data/scenarios/demo02.json \
    <execution.json> --cutoff 2026-10-03 [--no-defer] [--revision 2]
```

## 延误重规划例子结论（2026-10-01 至 10-10，`demo02`）

- 原计划用免费两跳 A→C→B 覆盖 10-03 工资 600（P1）与 10-06 房租 700（P2）。
- 10-03 早晨重开：第二跳 C→B 在途延误一天（10-04 才到账）；客户回款 IN1
  原定 10-05 到 500，实际 10-06 只到 300；同日起 A→B 加急通道当日到账、费率
  2%→5%。
- 修订计划：在途的 600 元保持在途（不从 C/A 重复动用）；为不延误 P1 工资，
  新增当日到账的加急 A→B 600，手续费 30 元（更贵但及时，理由写入 `choices`）；
  在途 600 于 10-04 到账，连同 10-06 部分到账 300 覆盖房租 700。
- 可选采购 X1（P3）800 从 10-08 推迟到 10-10，借助 10-09 回款 400 与剩余资金
  实付 600，仍有 200 缺口，在 `remaining_gaps` 中明确列出。
- 全程重放核对：期初 1300 + 收入 700 − 已付 1900 = 期末余额 70 + 手续费 30
  = 100，资金守恒、各账户余额非负。

## 小例子结论（2026-10-01 至 10-08）

- B 业务户 10-03 发工资 600（P1），但回款 500 在 10-04 才到账，不能提前用。
- A→B 直达隔日到账但收 2%；A→C 当日免费、C→B 隔日免费。
- 求解器选择免费的 A→C→B 两跳：10-01/10-02 筹资覆盖工资，
  10-03/10-04 再筹 200，与 10-04 回款 500 一起覆盖 10-05 房租 700（P2），
  总手续费 0。
- A 户仅剩 200，10-06 的可选采购 800（P3）无法覆盖，缺口 800 按位置输出。
- 穷举枚举与贪心目标元组一致，对账满足：
  期末余额 + 在途 + 手续费 = 期初 + 收入 - 已付支出。
- 执行记录可与计划不同（延误、部分、取消），重放时会暴露链式资金断裂；
  例如 T003 延误一天，C 户 10-02 无款发起 T004，直接报错。
